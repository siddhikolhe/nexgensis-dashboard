Choices I made:
- When a search term is active, I ignore the category filter and disable it in the UI, since DummyJSON can't search and filter by category in one request.
- Sorting is done client-side on whatever page comes back from the API, instead of relying on its sortBy/order params, because those aren't reliably supported across the /search and /category endpoints.
- Since DummyJSON's add/edit/delete don't actually persist anything server-side, I added a small localStorage layer (src/lib/localOverrides.js) that merges local changes on top of API responses, so the app behaves correctly after a refresh.

Problem I faced and how I fixed it:
Next.js's App Router throws a build error if useSearchParams() is used without a <Suspense> boundary. My product list page depends on the URL for page/search/filter/sort state, so I split it into an outer component wrapped in <Suspense> and an inner component that reads the params.
